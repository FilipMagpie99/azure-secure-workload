My project created hardened infrastructure as Terraform code. That code is only authoritative at apply time. Any change made outside Terraform (portal, CLI, compromised credentials) silently changes the hardened state. I decided to add a governance layer that detects misconfiguration happening outside of IaC, with enforcement (Deny) applied selectively where I tested the consequences first.a policy enters the set only if it pins down a hardening decision already made in this project. I am not building a production baseline. The catalog has dozens of applicable definitions; this project claims four things worth pinning down, so it has four assignments. 

HTTPS-only (App Service), effect Deny. The only Deny in the set. Enforcement was applied after the configuration it enforces was already deployed and audited green. I verified Deny behavior by attempting a non-compliant deployment and capturing RequestDisallowedByPolicy.

PostgreSQL Flexible Entra-only auth, effect Audit. The passwordless design can silently regress: password auth can be re-enabled alongside Entra auth without breaking anything visible. This assignment detects exactly that regression. Verified by negative test, I have enabled password auth flipped the resource to non-compliant within one scan, reverting restored compliant.

Storage network restrict, effect Audit. This assignment caught a misconfiguration, the Network Watcher flow log sink was deployed without network rules. The fix was three moves, first default_action Deny closes public access for everyone, bypass AzureServices keeps the platform write path open (verified by fresh flow log blobs after the change) and ip_rules with my dev IP is a deliberate narrow exception (without it I locked myself out of the data plane, management plane kept working). 

App Service public network access disabled, effect Audit, with Mitigated exemptions on both apps. Variant B keeps PNA enabled because SCM must be reachable for deployment from my admin station. This assignment makes the deviation from baseline explicit and formally recorded instead of silently non-compliant. The exemption category is Mitigated, the policy intent (no uncontrolled public path) is achieved by compensating controls, site and SCM ip_restriction default_action Deny plus application traffic exclusively through AppGW/WAF. There is no expiration date set, the compensation is a property of the architecture, not a temporary state. Residual risk is that the public endpoint still exists, attack surface is the ACL parser and SCM reachable from the dev IP.

Considered and rejected: storage PNA disabled (stronger than my design, would create permanent unplanned non-compliance), service endpoint policies (competing pattern to private endpoints), Entra admin provisioned (subsumed by Entra-only), Defender/ATP family (subscription-level cost decision).
